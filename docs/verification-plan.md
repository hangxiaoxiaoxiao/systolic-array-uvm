# 验证计划（讨论稿）

状态：已建立正式共用核心及五个组件自测，尚未编译或运行 UVM；两个层级的完整 TB 尚未接入。已有普通 SystemVerilog 教学示例的真实仿真基线，以及 Python 构建工具检查，不能据此宣称 UVM 或 DUT 验证通过。结构与证据边界见 [共用核心](core-architecture.md)，接口未定事项见 [规格问题](spec-questions.md)。

## 1. 题目明确要求

- 验证两个层级：`systolic_array` 模块，以及包含 FIFO、控制器、数据对齐和阵列的 `sub_sys` 子系统。
- 验证运算为 `C = A × B`，其中 A 为 `N × M`，B 为 `M × N`，C 为 `N × N`；矩阵元素为有符号数据。
- UVM 环境包含 driver、monitor、sequencer、scoreboard，支持约束随机数据和自动结果检查。
- 支持不同设计参数；子系统还需支持不同 `sys_clk` / `sr_clk` 关系。
- 尽可能复用两级验证组件，并提供验证计划、结构说明和明确的规格假设。
- 矩阵乘法 golden reference model 是必需项；实现 DUT RTL 不是要求。SystemVerilog 或 SystemC 的周期精确 DUT 模型是加分项。
- 提交源码和简短文档；具备仿真条件后，提供两个层级连续矩阵计算的日志和波形证据。

## 2. 建议的环境结构

以下为目标结构，尚未确定为接口规范。其中 transaction、数学参考模型和 scoreboard 已整理到 `tb/common`，接口 agent 和 environment 仍待正式接入。

| 组件 | 职责与复用方式 |
| --- | --- |
| 矩阵 transaction / sequence | 记录矩阵维度、A/B 数据和测试场景；共用数学数据生成，接口时序由 agent 处理 |
| 模块 agent | 按确认后的逐拍规则驱动 A/B、部分和及帧结束标记；monitor 重建实际输入与输出矩阵 |
| 子系统 agent | 按确认后的总线位序打包、写输入 FIFO、读输出 FIFO；monitor 依据真正接受的传输重建矩阵 |
| Golden reference model | 使用独立的矩阵乘法算法计算预期结果，显式处理符号扩展和最终确认的溢出规则；两级共用 |
| Scoreboard | 比较完整矩阵及元素位置，检查结果缺失、重复、顺序和事务是否全部完成；两级共用 |
| Coverage / 协议检查 | 数值、维度和运算场景覆盖尽量复用；时序、FIFO 和时钟检查按接口分别实现 |

预期结果以 monitor 确认的实际接收数据为依据，避免把尚未被 FIFO 接受的 sequence 数据当作已输入。模块接口的数据接收规则须先明确。结果采集依据 lane 和周期映射，不能用输出非零判断有效，也不能把帧结束标记当作逐拍 valid。

若增加 DUT 行为模型，应与数学参考模型分别实现并标明用途。协议尚未确认时，只能称为“基于假设的行为模型”，不能宣称与目标 RTL 周期一致。

## 4. 实施顺序

1. **共用核心整合（当前阶段）**：保留教学基线，将矩阵对象、数学计算及 scoreboard 分离为正式源码；用独立常量结果编写正常、错值、缺结果、回调顺序和对象复制自测，建立可重复的构建入口。UVM 实跑仍待可用环境。
2. **最小协议与模块接入**：只有 PDF，没有 DUT RTL。记录可替换的算术、逐拍调度、FIFO 位序、读延迟、复位及 M 规则假设；从最小配置接通 driver、monitor、sequencer、参考模型和 scoreboard。若使用自建行为模型，标明假设，不把它称为已确认的设计实现。
3. **连续计算**：两组数据刻意使用不同权重和结果，再扩展为多组；检查双缓冲切换和帧归属，保存波形。
4. **子系统接入**：复用矩阵 transaction、参考模型和 scoreboard，增加 FIFO agent，先同频，再改变频率比和相位。
5. **随机与边界**：在确认的合法参数域内增加随机矩阵、边界值、停顿、复位和多 seed 回归；依据 coverage 补充定向场景。

## 5. 建议的通过标准

- 所有已接受、且按复位规则仍应完成的输入事务，都在有界超时内产生且仅产生一组对应结果；结束时无遗留期望或实际结果。
- 每个结果矩阵的 `N × N` 个元素与参考模型一致；无未解释的 X/Z、协议错误或 UVM error/fatal。
- 定向、连续、参数与时钟场景全部完成；约定的功能覆盖点命中或记录合理豁免。随机 seed 数量和覆盖率门槛在协议确认后确定。
- 每次回归记录版本、DUT/模型类型、仿真器及版本、参数、seed、命令、结果和关键波形，使结果可复现。

## 6. 交付限制

当前已有共用核心源码、五个尚未运行的 UVM 组件自测、构建工具及普通 SV 基线记录。两个完整验证环境、连续矩阵和双时钟验证尚未完成，也没有目标 RTL 的验证结果。

没有真实 DUT 时，即使后续 TB 在行为模型上通过，也只能说明该模型和测试环境在所声明假设下相容，不能作为目标 RTL 已通过验证的证据。缺少 UVM 仿真器时，入口明确报告 `NOT_RUN`；Python 日志解析用例中的合成文本不作为仿真日志提交。
