# 待确认的规格问题（讨论稿）

状态：以下规格问题尚未解决，候选处理方式只是建议。普通 SV 教学模型已按局部假设运行，正式共用核心也已开始整理；这些工作不代表接口假设已获确认。优先级 P0 表示会影响最小测试的接口或结果定义，P1 表示会影响扩展场景。

已知条件：面试方只提供 PDF，没有 DUT RTL；当前本机没有可用的 UVM 仿真器。后续可先形成明确、可替换的模型假设继续实现，无需重新索取不存在的 RTL。

## 已明确的边界

- 目标是有符号矩阵乘法 `C = A × B`，本项目不另加独立的偏置矩阵。
- 模块配置包含 N 和 DIN_WIDTH；输入元素宽度为 DIN_WIDTH，结果元素宽度为 `2 × DIN_WIDTH`。
- 子系统总线宽度为 `2 × DIN_WIDTH × N`；每份输入总线数据包含 N 个 A 元素和 N 个 B 元素。
- 子系统数据读写与阵列计算使用两个时钟；`M_minus_one` 为 8 位。
- 模块级 `in_valid`、`out_valid` 的说明指向一组矩阵数据的结束位置，不能直接解释为普通流接口的逐拍有效信号。

## 需要形成书面约定的问题

| 优先级 | 问题 | 对 TB 的影响与建议 |
| --- | --- | --- |
| P0 | `in_valid` / `out_valid` 是单周期高脉冲还是翻转事件？结束标记与最后数据同拍吗？帧开始如何定位？ | 明确采样边沿、脉宽和首帧规则；driver、monitor 与断言必须使用同一份时序表。 |
| P0 | 每一拍、每个 `a_din` / `b_din` / `c_dout` lane 对应哪个矩阵元素？预装载、计算和流水排空从哪一拍计数？ | 先确认 `N=M=2` 的完整逐拍表，再推广；输出可能在结束标记前已经出现，不能只采集标记拍。 |
| P0 | 模块没有 M 端口时，如何识别 M、帧边界和权重切换？双缓冲何时加载、何时生效？ | 分别规定首帧、连续帧、帧间间隔和不同 M 帧的操作，不自行添加 DUT 控制信号。 |
| P0 | N×N 的 PE 阵列如何调度 `M≠N`？`c_din` 回环由谁提供，延迟多少拍，何时清零，分块尾部如何处理？ | 明确完整运算的外部职责及合法 M 域；在确认前仅把 `N=M=2` 作为候选起点。 |
| P0 | `M<N` 是否支持？“每 M 拍完成一组”的稳态吞吐描述适用哪些配置？ | 每组有 N² 个结果而接口每拍最多承载 N 个，完整输出至少占 N 拍；若持续每 M 拍一组，需解释 `M<N` 时的限制或额外机制，不能直接写通用吞吐断言。 |
| P0 | 乘积和累加分别使用多少位？结果溢出采用截断回绕、饱和还是报错？截断发生在每次累加还是最终输出？ | signed 已明确；仍需规定算术位宽和量化点。参考模型应显式实现确认后的规则。 |
| P0 | `din` 中 A/B 的高低位分区、元素顺序是什么？`dout` 每字对应 C 的哪一行或哪一组元素？ | 给出位切片公式及一个已知矩阵的打包例子；输入与输出重组据此实现。 |
| P0 | FIFO 在哪个边沿接受写/读？满/空标志在哪拍有效？输出是 FWFT 还是读请求后若干拍有效？ | 明确真正接受传输的条件和读延迟；monitor 不能只凭 `wr_fifo` / `rd_fifo` 认定数据已传输。 |
| P0 | 输出 FIFO 满时，控制器能否暂停阵列或缓存未写入结果？FIFO 深度和流控限制是什么？ | 确定允许的读暂停长度和无丢失条件；不能假设阵列一定支持任意反压。 |
| P0 | `M_minus_one` 何时锁存？何时允许更新？FIFO 中多帧数据存在时，每帧的 M 如何对应？ | 8 位编码能表示 1–256，但实际支持范围需确认；初始可建议固定 M 运行，不能据此宣称支持逐帧改变 M。 |
| P0 | 低有效复位是同步还是异步？两个时钟域如何退出复位？运行中复位会丢弃哪些输入和输出？ | 明确最短复位长度、是否清空 FIFO/权重/部分和，以及何时允许重新驱动；scoreboard 按规则清除被取消事务。 |
| P1 | 模块输入是否必须连续？帧内能否有空拍？子系统 FIFO 暂时为空时，控制器如何处理已启动的运算？ | 帧结束标记本身不足以表达每拍停顿；合法间隔确认前，不把插入空拍当作通用随机场景。 |
| P1 | 不同 `sys_clk` / `sr_clk` 关系的允许范围是什么？可否同频异相、非整数比、运行中改频或停钟？ | 初步建议分别验证总线较快、阵列较快和同频异相；动态改频/停钟仅在明确支持后加入。 |
| P1 | N、DIN_WIDTH 的合法范围与特殊值是什么？非二次幂 N、`N=1`、`M=1` 是否支持？ | 形成参数矩阵后再制定边界测试；避免把接口类型能表达的值都视为有效配置。 |
| P1 | 在输出无效时，`c_dout` 置零的精确周期规则是什么？首个结果和最后结果的延迟如何定义？ | 功能正确性、延迟和吞吐分开检查；输出为零可能是合法结果，不能当作无效标记。 |

## 建议首先定下来的最小合同

1. 基于现有 PDF 记录接口版本与未定项；后续若使用自建行为模型，应在源码、测试记录和文档中明确标注。另行解决 UVM 仿真环境。
2. 选择 `N=M=2`、DIN_WIDTH=8 作为讨论示例，给出两组连续矩阵的逐拍输入输出表。
3. 确定 signed 算术的累加与溢出规则，以及所有接口的采样边沿。
4. 子系统先约定一个固定 M、明确 FIFO 位序与读延迟；随后扩展到时钟关系、流控和参数边界。

以上四项是实施建议，尚未获得规格确认。任何临时假设应记录依据、影响的测试和替换位置；不能把模型自洽当作设计规格已获确认。
